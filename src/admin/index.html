Ручной запуск импорта
Список обновлений (LST) → сайт релизов releases.1c.ru → 1С:Решения, теги, переходы → сборки платформы. Обычно 5–10 минут (первый раз — дольше: страницы всех сборок платформы); повторный запуск безопасен. Так же раз в сутки обновляет воркер по расписанию — его логи в «Истории запусков».

Проекты releases.1c.ru ↔ приложения
Приложение = шаблон конфигурации (каталог в tmplts, например 1c/Accounting) + редакция. Проекты сопоставляются автоматически при импорте releases.1c.ru: по правилу «nick = шаблон + редакция», затем строго по совпадению версий. Ручная привязка имеет приоритет и импортом не перезаписывается.

Теги линеек (БУХ, ЗУП, УТ, УНФ…)
Теги ставятся на шаблон (все его редакции). Типовые 1С получают тег по имени шаблона, отраслевые и партнёрские решения — «на базе …» по «Базовой конфигурации» с 1С:Решения (официально, в приоритете), иначе по имени или по общим номерам версий с типовой (≥40 версий, ≥50%). Ручные теги имеют приоритет и пересчётом не перезаписываются. Автопересчёт — после каждого импорта LST.

Домен и HTTPS
Апдейкон установлен за внешним обратным прокси (Nginx Proxy Manager, nginx, Traefik): домен и HTTPS-сертификат настраиваются в нём, своего Caddy здесь нет.
Сейчас вы открыли админку как —
Адрес Апдейкона для прокси: http://updatecon:3000 (в Docker-сети прокси) или http://127.0.0.1:<WEB_PORT> (прокси на этом сервере).
Введите домен — Caddy автоматически получит сертификат Let's Encrypt и настроит редирект HTTP → HTTPS. Домен должен уже указывать на этот сервер (DNS A-запись). Чтобы вернуться к HTTP, очистите поле и нажмите «Применить».

Доступ к ИТС
Учётные записи портала 1С (releases.1c.ru, downloads.v8.1c.ru) для импорта обновлений. Первая — основная; остальные пробуются для продуктов, которых основная не видит (портал скрывает продукты без подписки). Перед сохранением учётка проверяется входом на releases.1c.ru; пароли хранятся в базе зашифрованными.
Часть сохранённых паролей ИТС больше не читается (сменился пароль базы данных) — добавьте эти учётки заново.
Пароль администратора
Логин задаётся в .env (ADMIN_LOGIN).
Адрес панели
Свой адрес вместо общеизвестного /admin — например, panel-7k2q. Старый адрес перестаёт открываться сразу, /admin отвечает «страница не найдена». Забыли адрес — он в логе веб-сервера: docker compose logs web | grep панель
Яндекс Метрика
Счётчик создаётся на metrika.yandex.ru с адресом этого сайта. Код на сайт ставится сам, переходы по страницам приложения тоже считаются. Панель администратора не отслеживается.
Цели для Метрики (JavaScript-события)
Метрика → Цели → Добавить цель → «JavaScript-событие», идентификатор:
chain — построена цепочка обновлений
download — переход к скачиванию обновления
chain_copy — цепочка скопирована
chain_share — скопирована ссылка на цепочку
fav — конфигурация добавлена в «Мои»
pwa_install — сайт установлен как приложение
script_chain — скачан скрипт обновления по цепочке
script_platform — скачан скрипт установки платформы
